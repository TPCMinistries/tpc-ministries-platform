# 10-02 · Scope member-facing tables to the owner

## Objective
Replace always-true policies (and fill `rls_enabled_no_policy` gaps) on tables the
authenticated browser client reads, with owner-scoped policies so each member can
read/write only their own rows. These tables CANNOT be locked to service-role —
they are read client-side as the logged-in member via `lib/supabase/server.ts` /
`lib/supabase/client.ts`.

## Background (verified this session)
- Member-facing reads confirmed: `families` (`app/(member)/family/page.tsx`),
  `sermon_notes` (`app/(member)/sermons/page.tsx`).
- 17 tables are `rls_enabled_no_policy` — several are member-facing and therefore
  currently BROKEN for client reads (e.g. teaching_progress, content_progress,
  member_prophecies). They need owner policies, not a lockdown.
- Ownership maps through the `members` table to `auth.uid()`. The exact owner
  column varies (`member_id`, `user_id`, `owner_id`) and MUST be introspected per
  table, not assumed.

## Candidate tables (member-facing — confirm + scope)
families, family_members, family_invites, sermon_notes, member_prophecies,
prophecy_prayer_requests, prophecy_tracking, teaching_progress, teaching_bookmarks,
content_progress, sermon_highlights, accountability_checkins, coaching_clients,
coaching_sessions, stream_attendance, prayer_partnerships, celebration_messages,
playlist_songs, points_history, member_onboarding (read side), and member volunteer
tables (volunteer_members, volunteer_availability, volunteer_hours,
volunteer_preferences, volunteer_schedules, volunteer_shifts, volunteer_signups).
Adjust membership based on 10-01's DEFER list.

## Tasks

<task id="10-02-1" title="Introspect ownership column per table">
For each candidate, query `information_schema.columns` for the owner key
(`member_id` | `user_id` | `owner_id` | `auth_user_id`). Determine the join path to
`auth.uid()` (direct `user_id = auth.uid()`, or via `members` where
`members.id = <table>.member_id AND members.user_id = auth.uid()`). Record a
per-table ownership map. Flag any table with no clear owner column for a decision.
</task>

<task id="10-02-2" title="Confirm client access + current policies">
Grep `.from('<table>')` to confirm authenticated-client reads and the operations
used (select/insert/update/delete). Snapshot current `pg_policies` rows for all
candidates (rollback source).
</task>

<task id="10-02-3" title="Author migration: owner-scoped policies">
Create `supabase/migrations/<ts>_rls_member_scoped_policies.sql`. For each table:
drop the always-true public policy, then create explicit policies:
- `SELECT` / `UPDATE` / `DELETE`: `TO authenticated USING (<owner = auth.uid mapping>)`
- `INSERT`: `TO authenticated WITH CHECK (<owner = auth.uid mapping>)`
Keep service-role implicit (it bypasses RLS). Keep any correct `is_tpc_admin()`
policy so staff retain access. Include verbatim rollback block.
Reference helper: reuse existing `is_tpc_admin()`; create a small `is_member_owner`
pattern inline per table rather than a generic catch-all.
</task>

<task id="10-02-4" title="db-safe approval gate">
Present migration SQL + per-table ownership mapping + effect + rollback. Wait for
explicit "APPROVED" before applying. Batch by table group if large (families,
prophecy/prayer, teaching, volunteer) for reviewable chunks. (autonomous: false)
</task>

<task id="10-02-5" title="Apply + verify owner isolation">
Apply migration(s). Verify with two JWTs (or simulated `auth.uid()`):
(a) member A reads own rows OK; (b) member A cannot read member B's rows;
(c) member A can insert/update only rows that resolve to their own ownership;
(d) the live member pages (`/family`, `/sermons`, teaching progress) still render
their data. Re-run `get_advisors` — candidates gone from always-true and no longer
`rls_enabled_no_policy`.
</task>

## Verification
- Every member-facing table has owner-scoped SELECT (+ INSERT/UPDATE as used).
- Cross-member read denied (isolation test passes for ≥3 representative tables).
- `/family`, `/sermons`, teaching-progress reads still work for the logged-in member.
- No candidate remains in `rls_policy_always_true` or `rls_enabled_no_policy`.

## must_haves
- Owner-scoped policies derived from the REAL owner column (introspected, not assumed).
- Member data isolation proven (A cannot see B).
- Member-facing client reads still function.
- Reversible migration(s) with rollback; staff `is_tpc_admin()` access preserved.
