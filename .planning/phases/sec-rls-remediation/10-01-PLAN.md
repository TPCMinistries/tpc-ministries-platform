# 10-01 · Lock admin/service-role-only tables

## Objective
Remove the public `USING(true)` ("always true") RLS policies from tables whose
ONLY application access is the service-role admin client (`createAdminClient`,
`lib/supabase/admin.ts`) or system/cron writes. The service role bypasses RLS,
so dropping the permissive public policy closes the anon/authenticated hole with
zero app impact. Tables that retain an `is_tpc_admin()` policy keep admin-via-browser access.

## Background (verified this session)
- `get_advisors` security shows 44 `rls_policy_always_true` + 17 `rls_enabled_no_policy`.
- Many always-true policies are named "Service role full access" but written
  `TO public USING(true)` — i.e. anon + authenticated get full read/write.
- VERIFIED admin-only (all `.from()` via `admin` client in `app/api/kenya/*`;
  authenticated client only does `auth.getUser()`):
  `kenya_trip_admin_payments`, `kenya_trip_mission_funds`,
  `kenya_trip_partner_proposals`, `kenya_trip_partners`.

## Candidate tables (verify each before dropping)
Confirmed admin/financial: kenya_trip_admin_payments, kenya_trip_mission_funds,
kenya_trip_partner_proposals, kenya_trip_partners.
To verify in-task (drop only if NO authenticated/anon client read exists):
kenya_trip_track_lead_notes, kenya_trip_track_plans, workspaces, workspace_members,
workspace_invites, message_queue, scheduled_notifications, workflow_executions,
search_logs, pastoral_care_notes (staff-written → likely admin-only).
DEFER to 10-02 if a member page/route reads the table via `lib/supabase/server.ts`
or `lib/supabase/client.ts`.

## Tasks

<task id="10-01-1" title="Classify candidates by client access">
For each candidate table, grep the codebase for `.from('<table>')` and determine
the client variable in scope (admin vs supabase/createClient). Produce a
CONFIRMED-ADMIN list (only admin-client or no app reads) and a DEFER list (any
authenticated/anon client read → goes to 10-02). Record the result.
</task>

<task id="10-01-2" title="Snapshot current policies (SELECT before modify)">
Run read-only `SELECT tablename, policyname, cmd, roles, qual, with_check FROM
pg_policies WHERE schemaname='public' AND tablename = ANY(<confirmed list>)`.
Save the output verbatim into the migration file header as the rollback source.
</task>

<task id="10-01-3" title="Author migration: drop public always-true policies">
Create `supabase/migrations/<ts>_rls_lock_admin_tables.sql`. For each CONFIRMED
table, `DROP POLICY "<exact always-true policy name>" ON public.<table>;`.
Do NOT drop `is_tpc_admin()`-scoped policies. Include a commented rollback block
that re-creates each dropped policy verbatim from the 10-01-2 snapshot.
</task>

<task id="10-01-4" title="db-safe approval gate">

</task>
