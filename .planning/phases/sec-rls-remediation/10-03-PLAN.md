# 10-03 · Harden public-form tables + final verification

## Objective
Keep public submission forms working (anon `INSERT`) while removing every
always-true `SELECT`/`UPDATE`/`DELETE` policy that would let the public read or
tamper with submissions. Then run the phase-level verification: advisor clean +
deny tests + functional smoke across admin, member, and public flows.

## Background (verified this session)
- Intentional public INSERT forms (KEEP insert): assessment_responses,
  assessment_responses_anonymous, contact_submissions, leads,
  kenya_debrief_registrations, blog_comments, poll_responses, member_onboarding,
  notifications, search_logs, workflow_executions.
- DANGEROUS leak to fix: `assessment_responses` has an always-true `UPDATE` policy
  (`assessment_responses_update_public`, qual=true) — anyone can rewrite any
  response. Remove it.
- Active code exists for get-involved + kenya registrations + assessments — the
  INSERT path MUST keep working.
